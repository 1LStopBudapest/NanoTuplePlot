# condor_analysis

Runs the `NanoTuplePlot/` pipelines on lxplus. One folder per
pipeline. `CutFlow_study_LL/` is the working example. Copy it to start a new one.

Every line you need to change is marked CHANGE. What they are, per file:

**write_condor_jobs_cutFlow.py** writes the condor submit file, one job per
(mass point, BR).

job time limits:
espresso     = 20 minutes
microcentury = 1 hour
longlunch    = 2 hours
workday      = 8 hours
tomorrow     = 1 day
testmatch    = 3 days
nextweek     = 1 week

**execute_condor_job.sh** what runs on the batch node.

- the pipeline folder name, in three places
- the `${1} … ${13}` slots, if your driver takes more flags than this one
- `${3}` and `${11}` in the CSV filename — they are token positions in the
  command line, so recount them if you reorder the flags

**move.sh** — packs everything and ships it to EOS.

submitFile_*.condor is generated by the python script don't edit it.

**To run:**

source ./move.sh                  # from inside your pipeline folder

Then on lxplus:

module load lxbatch/eossubmit     # once per session, to submit from EOS
cd /eos/user/..to your workspace
condor_submit submitFile_stop_cutFlow.condor
condor_q

Submit a couple of jobs first, before the whole grid.

## Output

Everything the jobs produce comes back in analysis_output/ right now just the plots and the .csv
